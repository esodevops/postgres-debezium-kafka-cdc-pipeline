How it works

This is a live view of your local PostgreSQL → Debezium → Kafka pipeline. The data generator creates synthetic ecommerce records; the dashboard does not generate metrics.

What is observed

PostgreSQL and Debezium are probed every five seconds. Kafka lag is the difference between partition high watermarks and this consumer group's committed offsets. Unknown offsets stay unavailable.

What the animations mean

Particles animate briefly after the consumer receives events. They demonstrate the architecture, not the current location of a record. Event details show actual source, connector, and receipt timestamps, plus the Kafka partition and offset.

Metric boundaries

Throughput uses changes in successfully processed counts between observations. Latency measures source timestamp to consumer receipt for retained live events from the last minute; snapshot reads and invalid clock differences are excluded. Error observations can include Kafka and decoding errors, not only rejected records.

Session and retention

Consumer restarts reset counters. Only 200 events are retained. Charts retain up to five minutes since the dashboard server started. Pause freezes the event list only; pipeline processing and analytics continue.
